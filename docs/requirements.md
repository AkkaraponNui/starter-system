# Requirements: ระบบลงทะเบียนกิจกรรม

> เอกสารนี้ผู้สอนเตรียมไว้ให้ ใช้เป็นข้อกำหนดของ `$supabase-feature` และเป็นเกณฑ์ทดสอบของ `$acceptance-test` อ้างถึงด้วยเลข US และ AC
>
> **ใน workshop:** US-1 ถึง US-3 ต้องทำ ส่วน US-4, US-5 และ US-6 เป็นงานเสริมสำหรับคนที่ทำทัน ลำดับที่แนะนำคือ US-2 → US-1 → US-3 → US-4 → US-5 → US-6

## US-1 สมัครสมาชิกและล็อกอิน

ในฐานะผู้เข้าร่วม ฉันต้องการสมัครและล็อกอินด้วยอีเมลและรหัสผ่าน เพื่อให้ระบบรู้ว่าการลงทะเบียนเป็นของฉัน

**เกณฑ์ยอมรับ**
- AC-1.1 เมื่อกรอกอีเมลและรหัสผ่าน (อย่างน้อย 6 ตัวอักษร) ที่หน้า `/login` แล้วกดสมัคร ระบบสร้างบัญชีและพาไปหน้า `/events` ในสถานะล็อกอินแล้ว
- AC-1.2 เมื่อล็อกอินด้วยรหัสผ่านผิด ระบบแสดงข้อความ "อีเมลหรือรหัสผ่านไม่ถูกต้อง" และยังอยู่ที่หน้า `/login`
- AC-1.3 เมื่อล็อกอินแล้ว แถบด้านบนแสดงอีเมลของผู้ใช้และปุ่มออกจากระบบ กดแล้วกลับเป็นสถานะยังไม่ล็อกอิน
- AC-1.4 เมื่อปิดแล้วเปิดเบราว์เซอร์ใหม่ภายในวันเดียวกัน ยังอยู่ในสถานะล็อกอิน

## US-2 ดูรายการกิจกรรม

ในฐานะผู้เข้าร่วม ฉันต้องการเห็นกิจกรรมที่เปิดรับพร้อมจำนวนที่นั่งคงเหลือ เพื่อเลือกกิจกรรมที่สนใจ

**เกณฑ์ยอมรับ**
- AC-2.1 หน้า `/events` แสดงกิจกรรมที่ยังไม่เริ่ม เรียงจากวันเวลาที่ใกล้ที่สุด โดยแต่ละรายการมีชื่อ, วันเวลาเริ่ม (เวลาไทย), สถานที่ และ "เหลือ X / Y ที่นั่ง"
- AC-2.2 ผู้ที่ยังไม่ล็อกอินเปิดหน้า `/events` ได้ และเห็นข้อมูลเหมือน AC-2.1
- AC-2.3 กิจกรรมที่เริ่มไปแล้วไม่แสดงในรายการ
- AC-2.4 ถ้าไม่มีกิจกรรมเลย แสดงข้อความ "ยังไม่มีกิจกรรมที่เปิดรับ"
- AC-2.5 จำนวนที่นั่งคงเหลือนับจากการลงทะเบียนของ**ทุกคน** แต่หน้าจอไม่แสดงว่าใครลงทะเบียนบ้าง

## US-3 ลงทะเบียนกิจกรรม

ในฐานะผู้เข้าร่วม ฉันต้องการลงทะเบียนกิจกรรม เพื่อจองที่นั่งล่วงหน้า

**เกณฑ์ยอมรับ**
- AC-3.1 เมื่อล็อกอินแล้วกด "ลงทะเบียน" ในกิจกรรมที่ยังมีที่ว่าง ระบบบันทึกการลงทะเบียน ที่นั่งคงเหลือลดลง 1 และปุ่มเปลี่ยนเป็น "ลงทะเบียนแล้ว"
- AC-3.2 ผู้ที่ยังไม่ล็อกอินกด "ลงทะเบียน" แล้วระบบพาไปหน้า `/login`
- AC-3.3 ลงทะเบียนกิจกรรมเดิมซ้ำไม่ได้ ระบบแสดง "คุณลงทะเบียนกิจกรรมนี้แล้ว" แม้จะพยายามส่งคำขอซ้ำโดยไม่ผ่านหน้าจอ
- AC-3.4 กิจกรรมที่ที่นั่งเต็มแสดงปุ่ม "เต็มแล้ว" ซึ่งกดไม่ได้ และถ้ามีคำขอลงทะเบียนเข้ามาตอนที่นั่งเต็ม ระบบปฏิเสธพร้อมข้อความ "ที่นั่งเต็มแล้ว"
- AC-3.5 ถ้าเหลือ 1 ที่ แล้ว 2 คนกดลงทะเบียนพร้อมกัน จะสำเร็จเพียง 1 คน
- AC-3.6 การลงทะเบียนถูกบันทึกในชื่อผู้ใช้ที่ล็อกอินอยู่เท่านั้น ส่ง `user_id` ของคนอื่นมาแทนไม่ได้

## US-4 ยกเลิกการลงทะเบียน (งานเสริม)

ในฐานะผู้เข้าร่วม ฉันต้องการยกเลิกการลงทะเบียน เพื่อคืนที่นั่งเมื่อไปไม่ได้

**เกณฑ์ยอมรับ**
- AC-4.1 ที่หน้า `/my` กด "ยกเลิก" แล้วยืนยัน การลงทะเบียนหายจากรายการ และที่นั่งคงเหลือของกิจกรรมนั้นเพิ่มขึ้น 1
- AC-4.2 ยกเลิกแล้วลงทะเบียนใหม่ได้ ถ้ายังมีที่ว่าง
- AC-4.3 ยกเลิกการลงทะเบียนของคนอื่นไม่ได้ แม้จะส่งคำขอตรงโดยไม่ผ่านหน้าจอ
- AC-4.4 กิจกรรมที่เริ่มไปแล้วยกเลิกไม่ได้ (ปุ่มไม่แสดง)

## US-5 กิจกรรมของฉัน (งานเสริม)

ในฐานะผู้เข้าร่วม ฉันต้องการดูรายการกิจกรรมที่ลงทะเบียนไว้ เพื่อจำได้ว่าต้องไปที่ไหน เมื่อไร

**เกณฑ์ยอมรับ**
- AC-5.1 หน้า `/my` แสดงกิจกรรมที่ฉันลงทะเบียนไว้ เรียงตามวันเวลาเริ่ม พร้อมชื่อ, วันเวลา และสถานที่
- AC-5.2 ผู้ที่ยังไม่ล็อกอินเปิด `/my` แล้วระบบพาไปหน้า `/login`
- AC-5.3 ถ้ายังไม่ได้ลงทะเบียนอะไร แสดงข้อความ "ยังไม่ได้ลงทะเบียนกิจกรรม" พร้อมลิงก์ไป `/events`
- AC-5.4 **บัญชี A ไม่เห็นการลงทะเบียนของบัญชี B** ทั้งในหน้า `/my` และเมื่อ query ตาราง registrations ด้วย publishable key ของบัญชี A

## US-6 อีเมลยืนยันการลงทะเบียน (งานเสริม)

ในฐานะผู้เข้าร่วม ฉันต้องการได้รับอีเมลยืนยันเมื่อลงทะเบียนสำเร็จ เพื่อมีหลักฐานและรายละเอียดกิจกรรมเก็บไว้

**เกณฑ์ยอมรับ**
- AC-6.1 เมื่อลงทะเบียนสำเร็จ ภายใน 1 นาทีมีอีเมลถึงอีเมลที่ใช้ล็อกอิน หัวเรื่อง "ยืนยันการลงทะเบียน: <ชื่อกิจกรรม>" เนื้อหามีชื่อกิจกรรม, วันเวลาเริ่ม (เวลาไทย) และสถานที่
- AC-6.2 เมื่อลงทะเบียนไม่สำเร็จ (ลงซ้ำ หรือที่นั่งเต็ม) ระบบไม่ส่งอีเมล
- AC-6.3 ถ้าส่งอีเมลไม่สำเร็จ การลงทะเบียนยังสำเร็จตามปกติ และหน้าจอแจ้ง "ลงทะเบียนแล้ว แต่ส่งอีเมลยืนยันไม่สำเร็จ"
- AC-6.4 ผู้รับคืออีเมลของผู้ใช้ที่ล็อกอินอยู่เท่านั้น ส่งอีเมลผู้รับอื่นมากับคำขอแทนไม่ได้
- AC-6.5 ค่าที่ใช้ส่งอีเมล (`GMAIL_USER`, `GMAIL_APP_PASSWORD`) ใช้ฝั่ง server เท่านั้น ไม่ขึ้นต้นด้วย `NEXT_PUBLIC_` และไม่อยู่ในโค้ดหรือ git

> **วิธีส่งอีเมล:** ใช้เซิร์ฟเวอร์ส่งอีเมลของ Gmail (SMTP) กับ App Password ของ**บัญชี Gmail ที่สมัครไว้ทดลองโดยเฉพาะ** ห้ามใช้ Gmail ส่วนตัวหรือบัญชีที่ทำงาน เพราะ App Password เข้าบัญชีได้ทั้งบัญชี ส่งถึงผู้รับได้ทุกอีเมล ประมาณ 500 ผู้รับต่อวัน

## ข้อกำหนดที่ใช้กับทุก story

- NFR-1 ทุกตารางเปิด RLS และ browser ใช้ publishable key เท่านั้น
- NFR-2 ไม่มี key หรือรหัสผ่านอยู่ในโค้ดหรือ git
- NFR-3 ทุกหน้ามีสถานะ กำลังโหลด / ไม่มีข้อมูล / ผิดพลาด และข้อความเป็นภาษาไทย
- NFR-4 ใช้งานได้บนมือถือ (กว้าง 375px ขึ้นไป) โดยไม่ต้องเลื่อนซ้ายขวา

ผู้สอนเพิ่มกิจกรรมผ่าน Supabase Table Editor อย่างน้อย 3 รายการ:

| ชื่อ | ที่นั่ง | ใช้ทดสอบ |
|---|---|---|
| อบรม Codex เบื้องต้น | 30 | ทางปกติ (AC-3.1, AC-4.1) |
| Workshop ห้องเล็ก | 1 | ที่นั่งเต็ม และกดพร้อมกัน (AC-3.4, AC-3.5) |
| กิจกรรมที่ผ่านไปแล้ว | 10 | วันเวลาเริ่มเป็นเมื่อวาน (AC-2.3, AC-4.4) |
